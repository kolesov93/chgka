# Task 0025: фото автора в медиаплашке вопроса

Статус: завершена и принята.

Branch: `task/author-media-presentation`.

## Цель

Дать ведущему управляемый телевизионный показ автора выбранного вопроса: сразу после остановки волчка приватно подготовить карточку в существующей плашке `Медиа`, а игрокам показать её только по явной команде.

## Согласованный UX

- При входе в `QUESTION_READING` плашка `Медиа` автоматически выбирает автора текущего вопроса как приватное превью. Игроки до команды ведущего продолжают видеть стол.
- Превью показывает фото или fallback-силуэт, имя и необязательный город в скобках. У сектора 13 вместо pack-фото используется статичное изображение сектора 13 без обычной авторской фотокарточки.
- Кнопка для выбранного авторского превью называется `Показать автора`. После показа карточка одновременно появляется у ведущего и игроков вместо стола; `Скрыть` возвращает стол, но приватное author-превью остаётся доступным для повторного выбора/показа.
- Обычный клик по inline image/audio/video по-прежнему заменяет выбранное превью. Пока идёт чтение, отдельная компактная кнопка `Автор` возвращает author-превью одним кликом.
- Автор доступен для показа только в `QUESTION_READING`. При переходе к обсуждению, досрочному ответу или ответу без обсуждения публичная карточка автоматически исчезает. Запуск чёрного ящика также заменяет её своей заставкой.
- В блице и суперблице после перехода к следующей части автоматически предвыбирается её собственный автор; авторы не входят в `Следующее медиа` и не образуют playlist.

## Техническое решение

- Расширить текущий opaque media-token специальным `presentation_kind: author`, связанным с точным `round_key`, `spin_id`, автором текущего normal-вопроса/части и pack-backed photo path. Файловый путь клиентам не отдаётся.
- Admin-only `admin_question.author_media` получает уже разрешённый author token и безопасные display metadata. Missing photo использует статичный frontend fallback; сектор 13 отмечается отдельным статичным asset.
- `admin_share_media` переиспользуется, но принимает author token только в `QUESTION_READING`. Shared state остаётся единственной authoritative presentation и публично добавляет только author display metadata, необходимые для карточки/reconnect.
- Обычный `current_media_catalog` и `next_media_in_section` не включают автора. Валидация author token отдельно сверяет текущий вопрос/часть, автора, фото и spin generation.
- Синхронные transitions очищают только публичный author presentation при любом штатном уходе из `QUESTION_READING`; обычное shared question media не получает нового автоматического lifecycle.
- Авторский token может оставаться пригодным как приватное превью до смены round/part/spin или TTL; его отсутствие в shared state достаточно, чтобы игроки снова увидели стол.

## Вне задачи

- Автоматический показ игрокам без команды ведущего, последовательный показ нескольких авторов и редактирование metadata пака.
- Добавление `author.jpg` в Markdown-media catalog или действие `Следующее медиа`.
- Изменение intro-слайдов и их текущего photo endpoint.
- Показ автора после начала обсуждения, в ответе/комментарии или в истории игры.

## Автоматическая проверка

- Normal/blitz/superblitz/sector-13 author descriptors и context-bound token validation, включая part/spin/TTL staleness и missing-photo fallback metadata.
- Handler pre-resolves author only для текущего admin question, rejects non-admin/stale/out-of-phase share and publishes reconnect-safe author metadata without paths.
- Transitions hide only a shared author when leaving reading via discussion, early answer or credit repayment; ordinary media remains unchanged.
- Frontend auto-selection, author re-selection, source/caption/fallback/special-sector rendering and absence from next-media controls.

## Реализация и локальная проверка

- Backend формирует отдельный author descriptor для точного normal-вопроса или текущей части блица, заранее выдаёт его только ведущему и валидирует opaque token по `round_key`, `spin_id`, scope, question UUID, metadata и TTL.
- Публичный показ переиспользует `shared_media`, но раскрывает только безопасные имя/город/asset metadata. Pack path и внутренний `media_ref` в public state не попадают.
- `Скрыть` оставляет author token пригодным для повторного показа в той же фазе; смена раунда/части/вращения и выход из чтения делают его непригодным или недоступным. Обычный media lifecycle не изменён.
- Frontend предвыбирает author-preview, позволяет вернуть его компактной кнопкой `Автор`, показывает pack photo/fallback/sector-13 asset и подпись `Имя (Город)` у ведущего и игроков.
- Локально проходят 260 backend-тестов, 14 frontend test-файлов, production build, `git diff --check` и native `docker compose config --quiet`.
- В in-app browser проверены normal photo/city, явный share, player reload, hide/re-show, inline-media re-selection, auto-hide на discussion/early answer, blitz fallback и static sector 13. Ошибок рендера нет; после reload браузер ожидаемо блокирует звук до пользовательского жеста.

## Ручной smoke

Пройден пользователем 2026-08-13.

1. Открыть `/admin` и `/play`, запустить игру, пропустить intro и выбрать сектор 3 sample-пака. После остановки волчка ведущий видит в плашке `Медиа` предвыбранное фото Андрея Козлова и подпись `Андрей Козлов (Казань)`, а игрок по-прежнему видит стол.
2. Нажать `Показать автора`. Ведущий и игрок одновременно видят одну карточку автора с тем же фото и подписью. Перезагрузить окно игрока: карточка восстанавливается; звук сам не запускается.
3. Нажать `Скрыть`: игрок возвращается к столу, у ведущего author-превью остаётся доступным. Показать автора повторно, затем начать обсуждение: карточка автоматически исчезает у обоих и больше не предлагается для показа в этой фазе.
4. Через Live Ops открыть сектор 2. Выбрать первую inline-картинку и показать её: `Следующее медиа` переходит только ко второй картинке вопроса и затем исчезает, не переходя к автору. Нажать компактную кнопку `Автор`: снова выбрана карточка автора, игрок до отдельного показа видит прежнее публичное состояние.
5. Через Live Ops открыть сектор 4 по очереди на частях 1, 2 и 3. На каждой части автор предвыбирается заново; часть 1 использует pack-фото, части 2/3 — статичный силуэт с именем. Затем открыть сектор 13: приватное и публичное author-превью используют `/images/intro/13.png` без обычной подписи автора.
6. Во время чтения показать автора и нажать `Досрочный ответ`: карточка сразу исчезает. Затем в Live Ops выставить кредит `Возврат назначен`, открыть обычный сектор, показать автора и нажать `Принять ответ без обсуждения`: карточка также сразу исчезает. Повторный быстрый `Показать`/`Скрыть` не должен давать ошибок или возвращать автора предыдущего раунда/части.
