# 0021: Стабильная раскладка управления intro

Branch: `task/stable-intro-controls`
Status: Completed

## Goal

Убрать вертикальные скачки основной кнопки ведущего при переходах между всеми intro-слайдами и сделать управление предсказуемым на desktop-экране.

## Result

- Intro-навигация перенесена из потока центрального слайда в отдельную секцию верхней части существующего sticky-sidebar ведущего.
- Секция имеет постоянную минимальную высоту и всегда сохраняет места кнопки музыки и основной кнопки следующего шага.
- После запуска или завершения музыки её кнопка остаётся disabled на прежнем месте; countdown и подписи меняются без сдвига навигации.
- Слайд с одной/тремя карточками и admin-only речь остаются в центральной колонке и больше не влияют на геометрию управления.
- Player presentation, Socket.IO contract и backend-state не изменены.

Выбрана существующая отдельная колонка: footer под слайдом продолжал бы зависеть от его высоты, а внутренний sticky/overlay мог бы перекрывать фотографии и речь. На узком viewport сохраняется обычный поток с доступом через прокрутку.

## CI regression follow-up

Python 3.14 выявил незакрытые тестовые SQLite connections из предыдущей journal-задачи. Pytest fixture теперь детерминированно закрывает каждый созданный в тестах `GameJournal`; runtime уже корректно закрывал его через FastAPI lifespan.

## Verification and acceptance

- 207 backend tests pass с `-W error` на Python 3.10 и в точной временной CI-среде Python 3.14.6.
- Все 11 frontend test files и production build проходят.
- GitHub Web CI run 39 на `5972b2e` полностью зелёный.
- Focused `/admin` + `/play` desktop-smoke принят пользователем 2026-08-11: кнопка остаётся под неподвижным курсором на слайдах `00`–`13`, состояния музыки стабильны, player UI корректен, финальный переход показывает стол `0:0`.

## Out of scope

- Мобильная админка, произвольный выбор/возврат слайда, autoplay и изменения backend intro-flow.
