# Формат пака вопросов

Пак — локальный каталог с 13 игровыми секторами. Перед запуском backend его нужно проверить тем же parser, который загружает вопросы в игру.

## Проверка пака

Из каталога `web_chgka/backend`:

```bash
python -m validate_pack /path/to/pack
```

Для корректного sample pack команда выводит:

```text
VALID: /absolute/path/to/pack
Questions: 13 (normal: 11, blitz: 1, superblitz: 1)
Authors: 19 (city: 2, photo: 12)
Parts: 6
Media: 9 (image: 5, audio: 2, video: 2)
```

Exit codes:

- `0` — пак корректен;
- `1` — путь или содержимое пака некорректны; причина выводится в stderr без traceback;
- `2` — команда вызвана без обязательного пути или с неверными аргументами.

## Структура каталогов

В корне обязательны каталоги `01`–`13`, по одному на сектор:

```text
pack/
├── intro.md              # необязательный текст вступления для ведущего
├── 01/
│   ├── question.md
│   └── author.jpg         # необязательное фото автора
├── 02/
│   ├── question.md
│   └── media/
│       └── image.jpg
├── 04/                  # пример блица
│   ├── question.md
│   ├── 01/
│   │   ├── question.md
│   │   └── author.jpg
│   ├── 02/
│   │   └── question.md
│   └── 03/
│       └── question.md
├── ...
└── 13/
    └── question.md
```

Дополнительные двухзначные цифровые каталоги, например `00` или `14`, запрещены. Именованные вспомогательные каталоги в корне допустимы и не считаются игровыми секторами.

## Текст вступления

Необязательный корневой `intro.md` содержит вступительную речь ведущего. Это обычный UTF-8 Markdown без frontmatter; backend преобразует его в HTML и отправляет только авторизованному ведущему через admin-only pack metadata. Пустой, бинарный, не-UTF-8 файл или symlink за пределы пака делает пак некорректным.

Медиа-ссылки в `intro.md` запрещены. Приложение статично поставляет музыку, стартовый слайд `00`, особый слайд сектора 13 и fallback-силуэт. Авторские экраны секторов 1–12 строятся из metadata и optional фотографий: обычный сектор показывает верхний вопрос, а блиц/суперблиц — три вложенные части в один ряд.

## Frontmatter и секции

Каждый `question.md` начинается с простого frontmatter. Поддерживаются только скалярные строки `key: value`, без YAML-списков и вложенных объектов:

```markdown
---
title: Название вопроса
type: normal
author: Имя автора
city: Город
author_photo: author.jpg
---

# Вопрос

Текст вопроса.

# Ответ

Текст ответа.

# Комментарий

Необязательный комментарий.

# Источник

Необязательный источник.
```

Поля:

- `title` — обязательно;
- `type` — `normal`, `blitz` или `superblitz`; если отсутствует, используется `normal`;
- `author` — обязательно для каждого вопроса и каждой части блица/суперблица;
- `city` — необязательный город автора;
- `author_photo` — необязательное имя `.jpg`, `.jpeg` или `.png` файла рядом с текущим `question.md`.

Другие frontmatter-поля сейчас не используются приложением. Заголовки секций должны быть H1 и идти в порядке `Вопрос` → `Ответ` → `Комментарий` → `Источник`.

`author_photo` не относится к question-media: его не нужно упоминать Markdown-ссылкой и нельзя класть в `media/`. Допустимо только простое имя файла непосредственно рядом с `question.md`; абсолютные пути, подкаталоги, traversal и symlink наружу запрещены. На intro-слайдах 1–12 имена авторов и города в скобках видят все клиенты. Обычный вопрос занимает одну карточку; три части блица/суперблица показываются тремя карточками в один ряд. Для каждой отсутствующей или не загрузившейся фотографии frontend независимо показывает встроенный анонимный силуэт. Для особого сектора 13 metadata автора всё равно обязательно, но intro использует статичный тематический слайд вместо авторской фотографии.

Для `normal` обязательны `Вопрос` и `Ответ`; подпапки `01`–`03` запрещены. Для `blitz` и `superblitz`:

- верхний `question.md` содержит общий `Вопрос`, но не `Ответ`;
- рядом обязательны ровно три каталога `01`, `02`, `03`;
- каждая часть имеет `type: normal`, собственные `Вопрос` и `Ответ` и не может содержать вложенные части.

## Медиа

Медиа кладутся в каталог `media/` рядом с соответствующим `question.md` и подключаются Markdown-ссылкой:

```markdown
![Картина](media/painting.jpg)
![audio](media/melody.mp3)
![video](media/clip.mp4)
```

Поддерживаемые расширения:

- изображения: `.jpg`, `.jpeg`, `.png`;
- аудио: `.mp3`, `.wav`, `.ogg`;
- видео: `.mp4`, `.webm`.

Локальный путь обязан начинаться с `media/` и после разрешения `..` и symlink оставаться внутри каталога текущего вопроса или части. Абсолютные пути и выход наружу запрещены. Каждый упомянутый файл должен существовать, а каждый файл внутри `media/` должен быть использован в Markdown. Внешние URL с `://` остаются обычными Markdown-ссылками и не считаются локальным медиа пака.

## Безопасность HTML

После преобразования Markdown backend санитизирует HTML по строгому allowlist. Обычное форматирование, таблицы и безопасные `http`/`https`/`mailto`-ссылки сохраняются. Скрипты, встроенные объекты, обработчики событий, inline-стили, опасные URL-схемы и произвольные `<img>` удаляются. Служебные media-placeholder создаются самим parser и остаются доступны управляемому media flow.

Это защищает браузер от исполняемого HTML внутри пака, но не отменяет структурную проверку через `validate_pack` и обычный контроль происхождения файлов.
