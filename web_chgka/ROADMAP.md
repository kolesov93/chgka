# CHGKA Web Roadmap

Дата ревизии: 2026-08-04.

Этот документ задаёт приоритетный backlog. Подпункты внутри задач — первая инженерная прикидка, а не зафиксированные решения. Перед началом каждой задачи нужно заново обдумать детали, обсудить спорные места и только потом принимать конкретное техническое решение.

## Workflow

1. Для каждой задачи создавать отдельную git branch.
2. В roadmap помечать задачу как `В работе` и указывать branch.
3. Создавать отдельный task-файл в `docs/tasks/`.
4. Перед реализацией записывать в task-файл цель задачи, текущий контекст, принятые решения и out of scope.
5. Работать над задачей в branch, обновляя task-файл при важных решениях.
6. Когда задача готова, проверить тесты/build, удалить закрытый пункт из roadmap и привести task-файл к лаконичному итоговому виду: что сделали, какие решения приняли и почему, что осталось.
7. Если в процессе появились новые работы, добавить их в roadmap отдельными пунктами.

## Приоритеты

### P0: техническая прочность

5. Авторизация и безопасность
   - Убрать dev default password из production-сценария или падать без `ADMIN_PASSWORD`.
   - Ограничить CORS в production.
   - Добавить TTL/revoke для admin tokens.
   - Санитизировать markdown HTML, если вопросные паки могут быть недоверенными.

6. Persist/recovery
   - Сейчас всё состояние in-memory. При рестарте backend игра теряется.
   - Минимальный вариант: snapshot state в JSON.
   - Более чистый вариант: Redis/SQLite для state, players, tokens и media tokens.

### P1: критичные фичи для live-игры

7. Режим бога: минимальный live-ops набор
   - Ручная правка счёта.
   - Отметить сектор сыгранным/несыгранным.
   - Отдельный disabled-режим для вопроса не нужен: сектор либо сыгран, либо нет.
   - Принудительно выбрать текущий сектор/раунд.
   - Принудительный переход в `PRE_ROUND`, `QUESTION_READING`, `DISCUSSION`, `TEAM_ANSWER`, `POST_ROUND`.
   - Скрыть текущее медиа.
   - Остановить все звуки.
   - Рядом с `Silence` добавить кнопку `Fade 3s`: по серверной команде все клиенты плавно снижают громкость играющей музыки/звуков до нуля за три секунды и затем останавливают их.
   - Все действия логировать в `game_state["logs"]`.

8. Медиа: управляемый media flow для вопроса и ответа — `В работе (этап 1: audio)`, branch: `task/media-audio-flow`, task: `docs/tasks/0007-media-audio-flow.md`
   - Поддержать картинки, аудио и видео как shareable media.
   - Обязательный regression-кейс: аудио `media/melody.mp3` из секции `question` sample-вопроса 03 должно открываться у ведущего и синхронно воспроизводиться/останавливаться у игроков, а не попадать в `unsupported_media_type`.
   - Медиа могут отличаться между фазой вопроса и фазой ответа.
   - Разделять медиа по секциям/фазам: `question`, `answer`, при необходимости `intro`, `comment`, `sources`.
   - В каждой секции хранить список медиа в порядке из markdown; ведущий выбирает конкретный элемент для показа.
   - Игроки не получают controls и не могут сами запускать/ставить на паузу медиа.
   - Добавить admin controls: показать, скрыть, play, pause/stop, перейти к следующему медиа.
   - Для видео/аудио решить синхронизацию через серверное состояние: media id, playback state, started_at/paused_at.
   - Добавить backend allowlist и media-token проверки для всех типов.
   - Добавить тесты, что media token нельзя использовать вне текущего раунда/части блица и вне разрешённой секции.

16. Inline-превью изображений в тексте ведущего
   - Вместо пустого placeholder показывать компактную картинку непосредственно в секции вопроса/ответа.
   - Клик выбирает медиа и открывает общий media control block, но не показывает его игрокам автоматически.
   - Делать после стабилизации общего media flow; эта задача не должна менять playback state или token contract.

### P2: закрыть заявленные режимы

9. Интро
   - Добавить фазу `INTRO`: `start_game` должен переводить игру из `LOGIN` в `INTRO`, а не сразу в `PRE_ROUND`.
   - При старте интро проигрывать `meeting.mp3`.
   - Игрокам сначала показывать `00_owl.png`.
   - Затем ведущий вручную переключает слайды авторов вопросов: `01.jpg`..`12.jpg`, затем `13.png`.
   - После последнего intro-слайда ведущий переключает на табло 0:0; в этот момент игра переходит в `PRE_ROUND`.
   - Ведущему показывать текущий intro-слайд, следующий шаг и индикатор оставшегося времени музыки, чтобы синхронизировать вступительное слово с концом трека.
   - Текст вступительного слова хранить вместе с паком вопросов и показывать только ведущему.
   - Фотографии/картинки интро должны стать частью пака вопросов, а не глобальными frontend assets.
   - До миграции можно использовать существующие `frontend/public/images/intro/*` как временный источник.

10. Чёрный ящик
   - Добавить metadata-флаг в frontmatter вопроса и частей блица/суперблица, например `blackbox: true`.
   - Прокинуть флаг через parser, pack admin info и `admin_question`.
   - В админской карточке вопроса явно подсвечивать, что сейчас чёрный ящик.
   - Добавить отдельную кнопку запуска музыки `yashik.mp3`; запуск должен быть осознанным действием ведущего перед чтением.
   - На первом этапе не менять scoring, таймер и player UI.
   - Конкретный UX кнопки и состояния проигрывания уточнить перед реализацией.

11. Личные вопросы
   - Добавить отдельный банк неигровых вопросов в metadata игры/пака, отдельно от 13 игровых вопросов.
   - Определить формат хранения, например отдельный файл `personal_questions.md/json` рядом с паком.
   - Загружать банк вместе с question pack и отдавать только ведущему.
   - Показывать ведущему список личных вопросов во время вращения волчка.
   - Дать ведущему возможность отметить вопрос заданным.
   - Заданные вопросы не удалять: переносить вниз списка и визуально отделять от незаданных.
   - Не менять scoring, фазу раунда, таймер обсуждения и player UI.

12. Завершение игры
   - Добавить `PHASE_GAME_OVER`.
   - При начислении шестого очка не обрывать раунд: игра должна перейти в `POST_ROUND`, чтобы ведущий мог разобрать ответ/комментарий.
   - В `POST_ROUND`, если у одной стороны 6 очков, кнопка ведущего должна вести не в следующий раунд, а в финал.
   - По кнопке ведущего всем показывается табло с финальным счётом и запускается `final.mp3`.
   - В `GAME_OVER` заблокировать spin/score/action-кнопки, кроме reset/new game.
   - Добавить backend-тесты: sixth point -> `POST_ROUND`; final button -> `GAME_OVER`.

13. Видеосвязь внутри сайта
   - Низкий приоритет, но выше мобильной версии.
   - Цель: заменить отдельный Zoom/Google Meet встроенной видеосвязью игроков и ведущего.
   - Рассмотреть WebRTC через готовую SFU/сервисную интеграцию, а не писать media server с нуля.
   - Продумать роли: ведущий, игроки, mute/unmute, камера/микрофон, reconnect.
   - Учитывать, что это существенно усложнит деплой, HTTPS, NAT traversal и стабильность live-игры.

14. Мобильная версия
   - Делать только player-only mobile: login, ожидание, стол/медиа, счёт, финальный экран.
   - Считать это низким приоритетом: основной сценарий игры остаётся desktop.
   - Мобильную админку не делать.
   - Проверить 360x640, 390x844, 768x1024 и desktop.
   - Добавить Playwright smoke/screenshot checks для ключевых экранов.
